# Аудит налоговой отчётности и разбор блокировок ФНС

## When to Use / Когда применять
- Пришло Решение о приостановлении операций по счетам (КНД 1160013), отказ в приёме отчёта (КНД 1166006) или требование ФНС.
- Пользователь просит найти ошибки в отчётности, составить план исправления, разобраться с блокировкой.
- Нужно проверить сформированный Контуром отчёт перед отправкой.
- Переход организации между режимами (УСН ↔ АУСН): что сдавать, в какие сроки, как считать взносы (см. references/ausn-transition-reporting.md).

## Жёсткие правила (всегда)
1. Перепроверять чужие диагнозы. Анализ другого ИИ, бухгалтера или пользователя — гипотеза, не факт: каждую цифру сверять с первичными документами (ведомости, реестр платежей, история ЕНС, тексты принятых и отклонённых отчётов). Неверный диагноз = неверный план = вторая волна проблем.
2. Расхождение между ведомостью и РСВ — не автоматически порча отчёта. Перед «понижающей» корректировкой проверить правовую основу: типовой случай — база взносов директора не ниже МРОТ с 01.01.2026 (см. references/ausn-transition-reporting.md).
3. Сроки и обязанность подачи — только по nalog.gov.ru или актуальным разъяснениям ФНС, не по памяти и не по задачам Контура: Контур часто настроен под другой режим, и его задачи врут. Пользователь проверяет и оспаривает утверждения — ошибка в сроке стоит ему денег.
4. Не называть основание блокировки, не прочитав Решение: там перечислены конкретные формы, периоды и сроки.
5. Сверять нарастающие итоги с ранее принятыми отчётами: сквозные контроля ФНС сравнивают новый отчёт с предыдущим периодом в базе — внутренне верный отчёт не пройдёт, если предыдущий период в базе ФНС с другими цифрами.
6. Не обещать снятие блокировки быстрее, чем позволяет п. 3.1 ст. 76 НК: автоматически, не позднее следующего рабочего дня после приёма отчёта (по факту 1–3 дня), заявление не требуется.

## Процедура разбора (по порядку)
1. Решение ФНС (КНД 1160013): основание (какая форма не представлена), счёт, что заблокировано. Важно: платежи в бюджет (налоги, взносы, пени, штрафы) проходят всегда.
2. Уведомление об отказе (КНД 1166006): коды ошибок и цифры расхождений — по ним арифметикой восстановить, что лежит в базе ФНС за предыдущий период, и локализовать испорченный отчёт.
3. Первичка: все расчётные ведомости за период, реестр платежей (что и когда реально уплачено), история ЕНС по датам (начисления и факт зачисления платежей — видно, дошёл ли платёж и по тому ли адресу).
4. План: порядок исправления (корректировка предыдущего периода → новый отчёт), доплаты, ожидаемые пени/штрафы, что делать не нужно.
5. Проверка готового отчёта (ниже) → отправка пользователем → контроль квитанции о приёме (она же доказательство для снятия блокировки).

## Проверка отчёта Контура перед отправкой
- Автоформирование идёт из НАСТРОЕННОГО режима: Контур под УСН при фактическом АУСН даёт неверный отчёт (типовая ошибка — месяцы после перехода на АУСН не обнулены). Сверять каждую строку с планом, а не с экранной сводкой.
- Исходящие XML Контура — кодировка windows-1251; read_file помечает их как binary. Читать через терминал (cat) или python с decode. Поля РСВ: СумВсегоПер = гр. 1, Сум1/2/3Посл3М = гр. 2/3/4; Раздел 3 (СвВыплМК): Месяц=1/2/3, СумВыпл, ВыплОПС, НачислСВ.
- Платёж ЕНП с неверным УФК в реквизитах получателя не зачисляется на ЕНС — проверять реквизиты платежки и факт зачисления по истории ЕНС.

## Документы от пользователя
- Пользователь складывает документы в папки (TEMP, TEMP/2, ...): прочитать всё в указанной папке, проверить каждый файл, расхождения докладывать явно.
- Документ без текстового слоя (скан, PDF-картинка): попросить пользователя прислать текст — он открывает документы у себя и копирует.

## Форма результата
- Итог — максимально подробный и точный отчёт, сохранённый файлом (docx по указанному пути): факты по организации, хронология, правовое основание со ссылками на нормы, сверка расчётов, пошаговый план с точными реквизитами заполнения (строка/графа/сумма), что делать НЕ нужно, сроки и блокировка, что осталось непроверенным, ключевые правовые источники.
- Регистр технический: пользователь хорошо разбирается в бухгалтерии — нормы, коды форм, строки/графы без разжёвывания, без воды.
- Каждую норму, на которой строится рекомендация, подкреплять источником (статья НК/ФЗ, письмо ФНС) — пользователь проверяет.
- Новые данные, меняющие диагноз, — править и переиздавать итоговый документ, а не дописывать «UPD» в переписке.
